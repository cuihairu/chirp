# Unity3D

Unity's official SDK covers the chat, social, voice and party message planes: `sdks/unity` in this repo is a **pure C# protocol stack** (no UnityEngine dependency, so its dotnet unit tests run standalone), plus a thin `ChirpManager` MonoBehaviour shell that handles main-thread dispatch. Connection, heartbeat, reconnect, kick and request timeouts are all built in, so the game side only deals with `Task` and events.

See [sdks/unity/README.md](https://github.com/cuihairu/chirp/tree/main/sdks/unity) for the complete source and details.

## How to integrate

1. **Protocol generated code**: copy `proto/csharp/*.cs` into `Assets/Chirp/Proto/` (generated by the repo-root `./gen_proto.sh`; protoc has `--csharp_out` built in, no plugin needed).
2. **SDK runtime**: copy `Runtime/Chirp/` and `Runtime/ChirpManager.cs` into `Assets/Chirp/Runtime/`.
3. **protobuf runtime**: add `Google.Protobuf.dll` (the unity release package of protobuf 3.27.x, or reference the same-named nuget package via NuForUnity).
4. Attach a `ChirpManager` in the scene (or `AddComponent<ChirpManager>()`).

Unity 2021.2+ (C# 9 / netstandard2.1) is enough, with either IL2CPP or Mono.

## Lifecycle

```text
ConnectAsync → LoginAsync → send/receive messages/events (main-thread callbacks) → auto reconnect on disconnect (AutoRelogin can replay login)
                                  ↓ KICK received (1005)
                              kick terminal state: no more auto reconnect, the player must log in again
```

- **Callback thread**: `On*` events are already dispatched back to the main thread by `ChirpManager` (an internal queue drained in `Update()`), so you can call Unity APIs directly.
- **Request-response**: correlated by sequence number; besides the convenience methods, any message can go through `RequestAsync` using the spec table (a 10s timeout throws `RequestError`).
- **Passive pushes**: heartbeats, message pushes (2005), read/typing/reaction/edit/delete notifications, party snapshots and so on do not go through the spec table — subscribe with `client.OnNotify(MsgID.Xxx, body => ...)`.
- **Offline delivery**: a send returning `TargetOffline` is not a failure — the message has already rolled into the other party's offline queue and is delivered on login; after receiving a message you must `AckChatMessage`, otherwise the server redelivers it.
- **Kick is terminal**: after being replaced the client no longer auto-reconnects, and the player must log in again.

## Minimal example

```csharp
_chirp = gameObject.AddComponent<ChirpManager>();
_chirp.AutoRelogin = true;                       // replay LOGIN automatically after a successful reconnect
_chirp.OnChatMessage += HandleMessage;
_chirp.OnKicked += reason => Debug.LogWarning($"kicked offline: {reason}");

await _chirp.ConnectAsync();
var login = await _chirp.LoginAsync(userId: "u1", deviceId: SystemInfo.deviceUniqueIdentifier);
_chirp.SendChatMessage("u1", receiverId: "", channelId: "g1", ChannelType.Group, "hello");

private void HandleMessage(ChatMessage m)
{
    // ... game logic ...
    _chirp.AckChatMessage(m.MessageId, "u1");   // must ack, otherwise redelivery
}
```

With a scaffold gateway, just `LoginAsync(userId, deviceId)`; when integrating JWT auth (`app_auth`), pass the third argument `token: jwt`.

## Multi-service connection topology

Chat, social, voice and party are separate services, each on its own `ChirpClient` (default development-topology ports):

| Plane | Message range | Entry point |
| --- | --- | --- |
| Chat | 2001-2258 | chat WS 7001 |
| Social (friends/blocklist/presence) | 3001-3029 | social WS 8001 (second connection) |
| Voice (WebRTC signaling) | 4001-4021 | voice WS 9001 (second connection) |
| Party | 7001-7027 | party WS 7501 (second connection) |
| Device push registration | 6001-6008 | app_gateway WS 5201 (second connection) |

Second-connection callbacks are dispatched through `RunOnMainThread` borrowing `ChirpManager`'s main-thread pump; the voice media plane uses Unity's official `com.unity.webrtc` package, with signaling (ICE/SDP relay) going through Chirp's 4007-4009.

## Current state and boundaries

- CI (`.github/workflows/unity-sdk.yml`) runs the `dotnet/ChirpSdkTests` unit suite on .NET 10, currently **107 cases** all green: frame codec, sequence correlation, timeouts, kick terminal state, heartbeat echo, reconnect lifecycle, hook wiring, FileMessageStore, word-filter pre-checks, plus edge fault injection (hook exceptions tolerated, stale transport replacement, malformed frames/PONG/kick garbage bodies, corrupt log replay) and `ClientWebSocketTransport` tests against a real loopback WebSocket (fragment aggregation, the 17MB cap, bidirectional close handshake); it also verifies `proto/csharp` has no drift.
- Coverage basis: coverlet cobertura with `proto/csharp` generated code excluded and deduplicated by file lines, at **89.2%** runtime line coverage (1436/1609); the residual gap is concentrated in `ChirpTransport.cs`'s OS-level socket exception paths.
- Unity is not distributed from nightly builds (the SDK is integrated as source, see "How to integrate" above); for the native C++ core's nightly artifacts see [Unreal](/sdk/unreal).
- Advanced social/party wrappers (UI components such as a friends panel or a party lobby) are not provided yet and will be added as game requirements arise; the iOS/Android native build scripts belonged to the old bridge approach and were removed along with the bridge.
