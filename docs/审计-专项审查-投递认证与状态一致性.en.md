# Special Review: Message Delivery Semantics, Authentication and Authorization, and Cross-Instance State Consistency

> Follows the table format of the documentation/source consistency audit standard (same as [Audit: doc consistency](/审计-文档一致性.en)).
> Audit time: 2026-10-11, baseline commit `e35a39e` (after the redis connection pool batch, before the C# wordlist test batch `cef69ac`; this review does not cover the test surface).
> Method: three-way parallel source corroboration (① the full delivery-semantics chain: send → store → fan-out → offline → replay → ACK; ② authentication/authorization: four direct entry points + the service plane + the token plane; ③ a full inventory of all 33 registered state tables), with every claim corroborated on both sides by file:line; **every P0/P1 item was re-verified against the source line by line on the day this was written**, and two inaccurate statements in the fork reports were corrected (see the D1 note and the A7 line numbers).
> Classification: [real defect] = behaviour is the opposite of a reasonable contract, or a promised surface is unimplemented; [documentation gap] = a deliberate source-side trade-off or fact is not documented, or the docs say the opposite; [needs decision] = the fix is a design decision; no code changes without a user decision.
> Fix principle: the source is the truth, so fix the docs; small uncontroversial real defects are fixed in the same batch and marked on the item; everything else goes on the decision list.

### Review passed (defences in place, no findings; recorded so they are not re-questioned)

- **Player-plane sender spoofing is intercepted**: the sending identity is forced to the authenticated identity (`chat_validation.cc:117-122`).
- **Player directory trust gate**: untrusted connections are refused bind/unbind (`player_directory.cc:511-514` DenyUntrusted).
- **Search identity binding**: queries are bound to the authenticated identity.
- **SameUser authorization override**: password/profile operations compare the target against the authenticated identity.
- **In-group permissions**: all admin operations pass through `RoleAtLeast` (the MODERATOR+ threshold, including mute 2250).
- **Device-plane identity stamping**: registration/update points use the server-side session identity (the notification plane excepted — see A1, that plane has no session identity at all).
- **Service registry fails closed**: with an empty registry, injection/forwarding is refused rather than allowed.
